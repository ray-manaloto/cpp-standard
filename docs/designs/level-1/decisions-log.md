## Research findings (2026-11-13)

- **CMake 4.5.0 (2026-11-12):**
  - `import std` no longer needs the experimental switch (MR 12547), and `CXX_MODULE_STD` and `CMAKE_CXX_COMPILER_IMPORT_STD` are gone.
  - `CMAKE_CXX_STDLIB_MODULES_JSON` is the fallback for the libc++ of p2996 and conda.
  - Presets schema 13 adds `${configurePresetName}`.
  - `cmake --list-presets=defined`.
  - `test_prep/all` targets are on by default; `CMAKE_TEST_BUILD_DEPENDS` is ignored now.
  - `CMAKE_COMPILE_WRAPPER_<NAME>` is a new hook for wrapping the compiler.
  - Open module bugs: #28242 (sibling targets with different flags, which matters for per-target sanitizer flags, so keep flags the same within one build tree), #28167, and #27962 (GCC 16 on Ubuntu 24.04 `import std`). The docs say Ubuntu before 26.04 ships a broken `libstdc++.modules.json`.
  - 4.5.0 is available through mise, Homebrew and conda-forge.
- **sccache:**
  - mise's latest is 0.19.0 (2026-10-24), which is also upstream's latest.
  - It caches clang and p2996 module builds. GCC module compiles skip the cache (#2630 is open), so GCC presets gain nothing from it.
  - Risks: #2650 (response files), #2863 (`SCCACHE_BASEDIRS` together with the preprocessor cache), #2593 (GHA backend goes read-only when rate-limited).
  - Use `SCCACHE_GHA_ENABLED`, and run read-only on PR jobs.
- **The fnox proxy TLS problem:**
  - Python 3.13+ turns on `VERIFY_X509_STRICT`, and the fnox proxy's CA certificate has no Authority Key Identifier, so verification fails. curl works.
  - Per-command workaround: use curl, or clear `VERIFY_X509_STRICT` in your own Python SSL context (verification stays on).
  - Durable fix: fnox should add an AKI to its CA (upstream; not done).
- **conda-forge GCC on osx-arm64** is built by `conda-forge/ctng-compilers-feedstock`: Darwin support came in PR #189 (2025-11-06), and 16.2.0 in PR #223 (2026-08-25).
  - It uses Iain Sandoe's Darwin patches, plus conda patch `0002-Make-stdlib-libc-the-default-for-macos-platforms`.
  - The recipe skips the `libstdcxx` and `libsanitizer` outputs on osx.
  - Result: GCC paired with libc++. It miscompiles `std::string` and `std::println` at low `-O`, and has no `import std` and no `<meta>`.
- **Upstream GCC 16 does not support aarch64-apple-darwin.** Homebrew and conda both use iains/gcc-16-branch. `libsanitizer/configure.tgt` has no aarch64-darwin entry. The private prototype's matrix says Homebrew gcc's ASan and UBSan work on the Mac, so that needs re-checking.
- **Reflection support:**
  - **GCC 16** ships P2996R13, P3394, P3491 and P1306 under `-std=c++26 -freflection`. About 41 reflection bugs are open, several of them involving modules (124200, 125398).
  - **Upstream clang 23.1.5 has no usable P2996.** Only pieces have landed. Endill on discourse (2026-07-02): "no support in Clang 23. Maybe ... Clang 24".
  - **clang-p2996** uses `-freflection-latest` and is labelled experimental. Its open issues include module problems (#262, #366).
- **CMake `import std`:** CMake 4.5 lists GCC 16 on macOS. That needs the std.cc fix, which is in Homebrew's 16.2.0 patch. clang-p2996 with its own libc++ is unverified.
- **Closest example projects:** none matches the whole target, and none has a 100% gate. The partial matches:
  - stephenberry/glaze CI: `gcc.yml` gcc16-reflection, and `p2996-reflection.yml`.
  - CppReflectionAD/cpp_reflection_ad: two-compiler P2996 presets, a macOS arm64 leg, and local runs match CI.
  - Cons-Cat/libCat: mise pins cmake, ninja and sccache, and CI uses jdx/mise-action.
  - mattgodbolt/specbolt: a CMake probe for reflection.
  - farmerpiki/conflux: an `import std` tri-state switch.
