# Read-only Codex hook discovery

From the CPP Standard checkout, run this against the intended already-running Codex app-server Unix socket.

```sh
python3 -I python/agents/hook_health.py \
  --socket "$control_socket" --home "$codex_home" --cwd "$project_cwd" \
  --expect "$reviewed_hooks_json"
```

Use absolute paths in the connection context and the expectation. Record the control server's launch profile and project trust from its launch receipt, and confirm they match the intended context before probing. Use the affected TUI and its thread for session-specific evidence. The command verifies home and cwd.

Build the private expectation from a prior reviewed native inventory or from a separate disposable reference install of the reviewed pin. In the native app-server `hooks/list` response for that reference cwd, select rows with the intended `pluginId`, `enabled: true` and `trustStatus: "trusted"`, then copy each row's `key` and complete `currentHash`. Record these pairs in the nonempty `hashes` object. Set `plugin` to that exact `pluginId` and `bundle` to the installed version directory being inspected. Review sources and resolve any missing or untrusted reference rows before recording the baseline. Keep it separate from the candidate and keep it private.

The command verifies the server's reported home and scoped cwd, exact selected inventory, enabled/trusted state, source path and full hashes. Exit 0 means discovery passed, 1 names a mismatch, and 2 means the evidence is incomplete. It emits only a reason or count and `runtime: NOT_RUN`. The qualified adapter is for Codex 0.171.0. It checks all config layers for existing plugin trust baselines before discovery because the native call can otherwise initialize those files. Keep config and baseline files stable during the probe. If the socket, server version or baseline prerequisites are missing, record incomplete evidence and use a disposable diagnostic context. Review hook changes in the affected TUI when authorized. Starting app-server against a configured home can start marketplace background work, so keep fixture servers disposable and production writers serialized.

## Publication contract

`python/agents/hook_health.py` exposes `publish_bundle(plan, stage_probe, live_probe)` for an additive version-directory move on the same filesystem. It leaves older directories in place. A publisher with a different bounded write set can call `guarded_publish(plan, stage_probe, live_probe, publish)`. The publisher owns exclusive writer coordination, including suspension or isolation of any native background refresh, and must declare every written or pruned root under the target plugin cache. The additive path requires an existing destination parent and a `local` or stable numeric Semantic Versioning directory that Codex will activate. An existing `local` or higher numbered version holds a numbered candidate. Unqualified version layouts hold before publication. Treat upstream upgrade entrypoints that prune the entire plugin directory as a write to that root.

Stage the exact reviewed Git source and full commit in a separate disposable Codex home outside the live home. Pass the exact Git source and SHA recorded in the activated marketplace receipt and the same selected native hook hashes for candidate and destination. This adapter checks plugins declared as local directories in that marketplace checkout, installed into its native staging cache. Pass two `NativeSocket` probes for the same absolute project cwd. The gate binds each probe to the home implied by its bundle and checks for shared cache directories before and after publication. Each socket verifies the server-reported home before discovery. Supply complete known active and resumable session dependencies as absolute regular-file paths, SHA-256 and full permission bits, including external targets and required adapters. The live version directory must use the exact marketplace, plugin and version suffix from staging. Use `None` when inventory is unknown. An empty mapping means the publisher verified there are no dependents. Keep all required generations and any symlink or mount aliases needed to reach them outside the declared write set. Retained files must have one hard link so an alias inside a write root cannot change them.

Candidate failure stops before the publisher runs. Publication success requires a second native read from the destination and a second retained-file check. The guard reads the catalog and file blobs from the exact local Git commit in the activated marketplace checkout. It checks canonical Git file modes and directory modes (stage with umask 022). This native installation omits source symlinks. Every staged regular file must have one hard link. The guard rejects other cache entries unless the plugin is declared at the repository root. For a root plugin, source review must include the generated Git and marketplace metadata that Codex copies. After reviewing the exact disposable native installation, record `reviewed_root_bundle_digest(bundle)` privately and supply it as `PublishPlan.reviewed_root_digest`. Keep that record independent of later staging changes and keep staging stable. A reinstall can change these metadata bytes and require a fresh review. The guard compares the contents and relative order of unrelated live discovery rows and holds when an already-trusted matching key would change its exact hash. Arrange separately reviewed trust and a separate launch context for intentional approval changes. Keep restart stopped on every failure, including one prefixed `post_publication:`, which can follow a completed move. Reconcile the live state while preserving all retained paths.

The publisher checks installed provenance metadata and relies on the caller to review the pinned source, supply the correct launch context, and enumerate dependencies. The control probe checks native discovery only. Runtime execution, ongoing cache refresh, cloud or Desktop writers and writes outside the controlled path need separate evidence.

## Adapter verification

When the adapter or its supported Codex version changes, run `CODEX_HOOK_FIXTURE_BINARY=/absolute/path/to/pinned/codex mise run agents:hook-native`. The task requires the binary explicitly. The fixture uses a local Git marketplace and disposable homes and verifies discovery and publication against the files Codex installs. The existing `agents:cov` gate runs the deterministic fixtures and the source-only macOS skill mapping check.
